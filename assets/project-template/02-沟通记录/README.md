# 沟通记录

> 每次会议保存**两层，缺一不可**：
> - **原文**：会议转写原样保存，不改动
> - **总结**：按约定结构整理的纪要
>
> 命名成对，靠后缀区分：`{MMDD}-{主题}-原文.md` / `{MMDD}-{主题}-总结.md`

## 会议索引

| # | 日期 | 主题 | 与会人 | 原文 | 总结 | 已回写 |
|---|------|------|--------|------|------|--------|
| 1 | | | | [原文](.) | [总结](.) | 否 |

「已回写」表示该会议的结论已更新到 `03_方案对齐.md`。**未回写的会议视为未处理。**

## 总结的结构要求

1. **说话人对照**：开头写明"说话人N = 谁"。说话人映射错了，整份纪要全错，必须先用硬事实交叉验证（年龄、公司、地域人脉、谁在给建议）。
2. **时间序章节**，不按主题归类。每章标题下加一行 `> **本章摘要**：……`，写清这章讲了什么、得出了什么结论或分歧。
3. **核心结论汇总表**。
4. **关键决策**：按「问题 → 方案 → 依据」三段式，不写清楚依据的决策等于没记。
5. **下一步行动**：`- [ ]` 格式，具体到谁、什么时间、做什么。
6. **出场角色表**：会议里出现的具名人物一个不漏，标明身份和与本次会议的关系。

## 硬规则

- **原话金句逐字保留**，用 `> **"原话"** —— 说话人X`。金句是后续理解当时的语义锚点。
- **具名实体（品牌、产品、人名）逐字保留**，不得泛化成"某品牌""某负责人"。
- **实体名与已有口径冲突时，不自行裁决**，强制记入「待核/差异」，由人确认。
- **摘要不等于标题复述**，要给出结论或分歧点。

## 摄入后必须做

```
原文归位 → 写总结 → 回写 03_方案对齐.md → 更新 README.md 变更日志 → 勾选「已回写」
```

最后一步不回写，前面全是白做。
