# 项目上下文

> 项目过程中获得的所有事实材料在这里登记。**客户提供不等于客户确认，原始资料不直接等于方案结论。**

## 目录

| 目录 | 放什么 | 规则 |
|------|--------|------|
| `01-客户原始资料/` | 客户给的文档、数据、截图 | 原样保存，不改写、不覆盖 |
| `02-我方调研/` | 行业分析、竞品拆解、技术验证 | 动态事实必须标检索日期，使用前复核 |
| `03-资料解读与映射/` | 对上述资料的解读、映射到我方能力 | 必须写清"能支持什么、不能证明什么" |
| `04-我方产品/` | 我方产品介绍、功能清单、报价口径 | 仅当产品资料没有独立产品库时使用 |

## 资料清单

| ID | 资料 | 来源 | 类型 | 取得时间 | 位置 | 状态 | 派生解读 |
|----|------|------|------|---------|------|------|---------|
| CTX-001 | | | 客户资料 / 我方调研 / 我方产品 | | | `context-only` | |

状态可用：`context-only`（仅作背景）、`candidate-evidence`（单方自述，待验证）、`validated-evidence`（已验证）、`superseded`（已被替代）。

## 使用规则

1. 新资料先登记到本清单，再放入对应子目录。**不登记的等于不存在**。
2. 客户原始文件原样保存，要做批注就写在 `03-资料解读与映射/`。
3. 资料里的说法进入方案前，必须经 `03_方案对齐.md` 的主张登记，不直接引用。
4. 解读先作为候选主张，经客户确认后才升级为共识。
